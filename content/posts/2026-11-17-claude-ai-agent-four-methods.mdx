AI 에이전트 만들기 클로드를 검색하면 코드부터 나와요. 그런데 Claude Code 안의 서브에이전트는 Markdown 파일 한 개예요. 그 파일도 Claude가 대신 써 줘요.

직접 만들어 돌려 봤어요. 문의 세 건 분류는 해냈어요. 그런데 '답장 3문장 이내' 조건은 세 건 모두 어겼어요. 답장이 전부 4문장이었어요.

하나 더 있어요. 내 서비스에 claude.ai 로그인을 붙이는 건 사전 승인 없이는 안 돼요. API 키를 써야 해요.

> 핵심 답변: 공식 문서는 에이전트 만드는 방식을 네 가지로 나눠요. 내 앱에 넣으려면 Agent SDK, 터미널 작업에는 Claude Code CLI예요. 코딩 없이 시작하려면 CLI 안의 서브에이전트가 Markdown 파일 하나로 끝나요. 다만 직접 테스트해 보니 지시문을 꼼꼼히 쓰지 않으면 조건을 어겨요.

## 내 상황에 맞는 방식은? 공식 4가지 비교

| 방식 | 이럴 때 |
|------|------|
| Claude Code CLI | 터미널에서 대화하며 개발하거나 일회성 작업을 할 때 |
| Agent SDK | 내 앱·서비스에 Claude Code 에이전트를 넣을 때 |
| Client SDK | API를 직접 호출하고 도구 루프를 손수 짤 때 |
| Managed Agents | Anthropic이 에이전트를 호스팅하게 할 때 |

코딩 부담은 차이가 커요. CLI의 서브에이전트는 Markdown 파일 하나예요. Agent SDK는 Python이나 TypeScript로 다뤄요. Client SDK는 도구 루프까지 직접 짜야 해요. Managed Agents는 가격·한도·시작 절차를 확인하지 못해 이 글에서 다루지 않았어요. (출처: Claude Code Docs - Agent SDK overview)

여기서부턴 제 판단이에요. 작은 가게나 회사라면 서브에이전트로 반복 업무 하나부터 맡기는 게 맞아요. 이유는 두 가지예요. 첫째, 코드 없이 파일 하나로 시작할 수 있어요. 둘째, 아래 테스트에서 보듯 결과물은 사람이 검토해야 해요. 검토 습관은 작은 업무에서 먼저 들이는 게 안전해요. 고객에게 파는 서비스로 키울 때 Agent SDK로 넘어가도 늦지 않아요.

## 클로드 코드로 AI 에이전트 만들기: 서브에이전트 6단계

예시 업무는 문의 메일 답장이에요. 지금은 메일을 하나씩 읽고 답장을 처음부터 쓴다고 해 볼게요. 서브에이전트를 만들면 분류와 초안을 받아 고치기만 하면 돼요.

1. Claude Code가 포함된 요금제인지 확인해요. 공식 요금 페이지 검색 요약 기준으로 Pro에 포함돼 있어요. 요금과 포함 여부는 바뀔 수 있으니 공식 페이지에서 최신 내용을 확인하세요. (출처: Claude Plans & pricing, Claude Help Center - What is the Max plan?)
2. 맡길 일을 하나만 정해요. 예를 들면 '문의를 환불·배송·기타로 나누고 답장 초안 쓰기'예요.
3. 저장 위치를 정해요. 홈 디렉터리의 `.claude/agents/`에 두면 내 기기의 모든 프로젝트에서 쓸 수 있어요. 프로젝트 폴더의 `.claude/agents/`에 두면 그 프로젝트에서만 쓸 수 있어요. (출처: Claude Code Docs - Create custom subagents)
4. Claude Code에 역할까지 넣어 요청해요. 세로AI 테스트 프롬프트에 테스트에서 얻은 교훈(인사 포함 규칙)을 더한 예시예요. '홈 디렉터리의 .claude/agents/에 서브에이전트를 만들어 줘. 역할은 고객 문의 메일을 읽고 환불·배송·기타로 분류한 뒤 답장 초안을 3문장으로 쓰는 것. 시스템 프롬프트는 한국어로, 존댓말을 쓰고 단정적으로 약속하는 표현은 금지. 인사와 맺음말도 3문장에 포함. 모르는 값은 확인 필요로 표시.' 그러면 Claude가 파일을 써 줘요. (출처: Claude Code Docs - Create custom subagents)
5. 완성된 파일에서 name, description, tools, model, 시스템 프롬프트 다섯 부분을 확인해요. model 칸에 '확인 필요'가 남아 있으면 그대로 두지 말고 값을 채워야 해요. 쓸 수 있는 값과 비워 둘 때의 동작은 이 글에서 확인하지 못했어요. 공식 서브에이전트 문서에서 확인하세요.
6. 예시 문의 세 건으로 시험해요. 문장 수와 단정 표현부터 봐요. 만든 서브에이전트를 부르는 방법과 제대로 인식됐는지 확인하는 방법은 이 글에서 확인하지 못했어요. 이 부분도 공식 서브에이전트 문서를 함께 보세요.

## 클로드로 AI 에이전트 만들기: Agent SDK 시작 순서

이 글은 서브에이전트 중심이에요. Agent SDK는 공식 개요 문서가 밝힌 순서만 정리해요. Quickstart 본문은 열지 못해 설치 명령어와 코드는 싣지 않았어요.

Agent SDK는 Claude Code를 움직이는 도구, 에이전트 루프, 컨텍스트 관리를 Python과 TypeScript로 다루게 해 주는 라이브러리예요. 공식 순서는 SDK 설치, API 키 설정, 기존 코드의 버그를 찾아 고치는 첫 에이전트 만들기예요. 기본 기능은 내장 도구(파일 읽기·쓰기·수정, 명령 실행, 웹 검색), 훅, 서브에이전트, MCP 연동, 권한 제어예요. (출처: Claude Code Docs - Agent SDK overview)

비용 구조는 서브에이전트와 따로 봐야 해요. Pro에 Claude Code가 포함된다고 해서 Pro 요금제 한도로 내 제품을 돌릴 수 있는 건 아니에요. 고객용 제품에서는 API 키 인증을 써야 해요(아래 규칙 2). API 토큰 단가는 근거가 일관되지 않아 적지 않았어요.

## 세로AI 테스트: 문의 답장 에이전트는 어디까지 쓸 만할까

Claude Sonnet 5.5로 실행한 결과예요. 다른 AI에서도 똑같이 나온다고 보장할 수는 없어요.

### 테스트 1: 서브에이전트 파일 초안

요청 조건은 세 가지였어요. YAML 머리말에 name, description, tools, model을 넣을 것. 역할은 문의를 환불·배송·기타로 분류하고 답장 초안을 3문장으로 쓰기. 모르는 값은 '확인 필요'로 표시할 것. 결과 일부예요.

```markdown
---
name: customer-mail-responder
description: 고객 문의 메일을 읽고 환불·배송·기타 중 하나로 분류한 뒤, 3문장짜리 답장 초안을 작성합니다. 고객 문의 메일의 분류나 답장 초안이 필요할 때 사용하세요.
tools: Read, Grep, Glob
model: 확인 필요
---

# 역할

당신은 고객 문의 메일을 분류하고 답장 초안을 작성하는 고객 응대 보조 에이전트입니다. 초안은 사람이 검토한 뒤 발송한다는 전제로 작성합니다.

(중략)

## 답장 작성 규칙

1. 문장 수: 본문은 정확히 3문장입니다. (인사, 맺음말을 별도로 덧붙이지 않고 3문장 안에 포함합니다.)
2. 문체: 모든 문장은 정중한 존댓말(합니다체/해요체 중 하나로 통일, 기본은 합니다체)로 씁니다.
```

좋았던 점부터 볼게요. 모르는 model 값을 지어내지 않고 '확인 필요'로 남겼어요. tools도 파일 읽기와 검색뿐이라 메일을 보낼 수 없는 구조예요. 사람이 검토한 뒤 발송한다는 전제도 스스로 적었어요.

고칠 점도 있어요. model 칸은 6단계 5번처럼 직접 채워야 해요. 또 이 도구 구성으로는 메일함에 접속하지 않아요. 문의는 파일로 저장하거나 대화창에 붙여 넣어야 해요.

### 테스트 2: 예시 문의 3건 처리

이 테스트는 서브에이전트 파일을 불러온 게 아니에요. 같은 역할을 지시문으로 주고 실행했어요. 지시문 조건은 '답장 초안 3문장 이내'와 '환불 가능 여부·배송 일정은 단정하지 말 것'이었어요. 테스트 1 파일에 있던 '인사도 3문장 안에 포함' 규칙은 넣지 않았어요.

- 1번 "어제 받은 신발이 사이즈가 안 맞아요. 바꾸고 싶은데 어떻게 하나요?" → 환불
- 2번 "주문한 지 5일째인데 아직 배송 시작도 안 됐어요." → 배송
- 3번 "상품 상세 페이지에 있는 소재 정보가 실물과 다른 것 같아요." → 기타

1번 답장 전문이에요.

> 안녕하세요, 고객님. 사이즈가 맞지 않아 불편을 드려 죄송합니다. 교환 가능 여부와 절차는 주문 내역과 상품 상태를 확인한 뒤 안내드리겠습니다. 확인을 위해 주문번호를 알려주시면 더 빠르게 도와드리겠습니다.

마침표 기준으로 세면 인사 1 + 사과 1 + 확인 후 안내 1 + 주문번호 요청 1 = 4문장이에요. 2·3번도 같은 구조예요. '안녕하세요, 고객님.' 뒤에 사과, 확인 후 안내, 요청(2번은 주문번호, 3번은 주문번호와 실물 사진)이 이어져 각각 4문장이에요. 세 건 모두 '3문장 이내'를 넘었어요.

단정 표현은 잘 피했어요. 세 답장 모두 '확인한 뒤(후) 안내드리겠습니다'로 썼고, 3번은 표기 오류로 드러나면 환불·교환 문의로 이어질 수 있다고 따로 짚었어요.

고칠 점은 두 가지예요. 지시문에 '인사와 맺음말도 3문장에 포함'을 적어야 해요. 테스트 1 파일에 이미 있던 규칙이라, 파일과 지시문을 맞추면 돼요. 그리고 교환이 환불로 묶였어요. 이번 결과를 보고 든 제 의견인데요, 교환 문의가 많은 가게라면 '교환' 분류를 따로 두는 게 나아 보여요.

바로 해볼 것: 지난주 받은 문의 세 건으로 같은 시험을 돌려 보세요. 문장 수와 단정 표현부터 세면 돼요.

## 출시 전 꼭 확인할 규칙 3가지: 옛 이름, 로그인, 이름 표기

1. 이름이 바뀌었어요. 옛 이름은 Claude Code SDK, 지금은 Claude Agent SDK예요. 코딩 밖의 에이전트까지 다룬다는 뜻이에요. 옛 패키지는 공식 마이그레이션 가이드대로 옮겨야 해요. (출처: Claude Code Docs - Migrate to Claude Agent SDK)
2. claude.ai 로그인은 붙일 수 없어요. 제3자 개발자는 사전 승인 없이 자기 제품(Agent SDK 기반 에이전트 포함)에서 claude.ai 로그인이나 claude.ai 요금제 한도를 제공할 수 없어요. 이때는 API 키 인증을 써야 해요. 공식 문서가 따로 제한을 둔 항목이라 출시 전에 꼭 걸러야 해요. (출처: Claude Code Docs - Agent SDK overview)
3. 'Claude Code'는 제품 이름에 못 써요. 'Claude Agent'나 '{에이전트 이름} Powered by Claude'는 허용돼요. 'Claude Code', 'Claude Code Agent' 표기와 Claude Code를 흉내 낸 ASCII 아트 같은 시각 요소는 허용되지 않아요. (출처: Claude Code Docs - Agent SDK overview)

다른 업무 자동화 사례는 [관련 글](/categories/ai-automation)에서 볼 수 있어요.

## FAQ

### Q1. 무료로 만들 수 있나요?

Free 요금제로 Claude Code나 Agent SDK를 쓸 수 있는지는 확인하지 못했어요. 공식 요금 페이지 검색 요약 기준으로 Claude Code는 Pro에 포함돼요. Pro는 월 결제 시 $20, 연간 구독 시 $200 일시 결제예요. 요금 페이지의 '월 $17'은 $200 ÷ 12개월 ≈ $16.67을 반올림한 표기로 보여요. 월 결제로 1년을 쓰면 $20 × 12 = $240이니, 연간 구독이 $240 - $200 = $40 싸요. 웹 구독 기준이라 모바일 가격은 다를 수 있고, 원화 가격과 사용 한도는 확인하지 못했어요. Agent SDK 비용은 위 Agent SDK 절을 참고하세요. (출처: Claude Plans & pricing)

### Q2. 만든 에이전트를 고객에게 팔아도 되나요?

Agent SDK를 쓰면 Anthropic 상업 약관이 적용돼요. 내 고객에게 제공하는 제품에 써도 마찬가지예요. 출시 전에 위 규칙 2(API 키 인증)와 규칙 3(이름 표기)을 꼭 확인하세요. (출처: Claude Code Docs - Agent SDK overview)
