무료 claude.ai 계정으로는 클로드 코드를 쓸 수 없어요. 요금제 비교표의 Claude Code 항목을 보면 Free 칸은 "No", 유료 플랜 칸은 "Yes"예요. 설치는 명령어 한 줄이면 끝나요. 시간을 잡아먹는 건 그 앞의 계정 확인과, 윈도우에서 PowerShell과 CMD를 구분하는 일이에요.

> 핵심 답변: 유료 플랜이나 Console 계정이 있는지 확인하고(1단계), 내 셸에 맞는 명령으로 설치하세요(2단계). 새 터미널에서 claude --version으로 확인한 뒤 로그인하고(3단계), 반복하는 요청은 SKILL.md 스킬로 저장해 두세요(4단계).

## 1단계: 계정과 환경 확인

### 무료로는 쓸 수 없어요

공식 설치 문서 기준으로 클로드 코드를 쓰려면 Pro, Max, Ultra, Team, Enterprise, Console 계정 중 하나가 있어야 해요. 무료 claude.ai 플랜에는 클로드 코드가 포함되지 않아요. 그러니 설치 명령보다 내 플랜이 Free인지 유료인지부터 보세요. claude.ai에서 플랜 이름을 보여 주는 메뉴의 정확한 위치는 확인되지 않았어요.

Console 계정은 claude.ai 구독과는 별개인 API 계정이에요. 쓴 만큼 내는 방식으로 보이지만 가입 절차와 요금 수치는 확인되지 않았어요. 무료 체험이나 크레딧을 주는지도 확인되지 않았어요. (출처: [Claude Code 설치 문서](https://docs.claude.com/en/docs/claude-code/setup))

### 요금: Pro 월 $20, Max 월 $100부터

Pro는 월 결제 시 $20, 연간 결제 시 월 $17이에요. 연간 결제는 $200을 한 번에 내요. 계산해 보면 이렇게 돼요.

- 연간 결제의 월 환산: $200 ÷ 12 = 약 $16.67, 요금제 페이지에는 $17로 표기
- 1년 총액 비교: 월 결제 $20 × 12 = $240, 연간 결제 $200, 차이는 $240 − $200 = $40

Max는 월 $100부터예요. Team, Enterprise, Ultra 요금은 확인되지 않았어요. 요금은 바뀔 수 있으니 결제 직전에 [요금제 페이지](https://claude.com/pricing)에서 다시 확인하세요. (출처: Claude 요금제 페이지)

### 사용량 한도는 웹·앱과 같은 풀에서 빠져요

클로드 코드 사용량은 웹, 데스크톱, 모바일과 같은 풀에서 차감돼요. 한도는 5시간 단위로 롤링 초기화되고, 유료 플랜에는 주간 한도가 따로 있어요. 남은 양은 claude.ai의 Settings > Usage에서 볼 수 있어요.

요금제 페이지에는 Pro와 Max의 메시지 수나 토큰 수가 없고 "5x" 같은 배수 표현만 있어요. 한도에 닿았을 때 정확히 어떻게 되는지도 확인되지 않았어요. (출처: Claude 요금제 페이지)

여기서부턴 제 의견이에요. Pro로 시작해 일주일 동안 Settings > Usage를 지켜보세요. 5시간 한도에 걸려 작업이 끊기는 일이 주 3회를 넘으면 그때 Max를 따져 봐도 늦지 않아요. 주 3회는 공식 기준이 아니라 제가 잡은 출발점이에요.

### 내 컴퓨터에서 돌아가는지

- 운영체제: macOS 13.0 이상, Windows 10 1809 이상(또는 Windows Server 2019 이상), Ubuntu 20.04 이상, Debian 10 이상, Alpine 3.19 이상
- 하드웨어: RAM 4GB 이상, x64 또는 ARM64 프로세서
- 셸: Bash, Zsh, PowerShell, CMD 중 하나
- 그 밖에: 인터넷 연결, Anthropic 지원 국가

설치 문서에는 'Anthropic 지원 국가'라는 조건만 있고 한국이 포함되는지는 적혀 있지 않아요. 결제 전에 Anthropic의 지원 국가 목록에서 확인하세요. (출처: Claude Code 설치 문서)

## 2단계: 내 창에 맞는 명령으로 설치

명령은 하나만 실행하면 돼요. 고를 기준은 지금 명령을 입력할 창이에요.

### macOS, Linux, WSL

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

### 윈도우는 창 종류에 맞는 명령을 쓰세요

PowerShell 명령을 CMD에 넣거나 그 반대로 하면 명령어 구문 오류가 나요. 지금 연 창이 어느 쪽인지 먼저 보세요.

#### PowerShell

```powershell
irm https://claude.ai/install.ps1 | iex
```

#### CMD

```cmd
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

네이티브 윈도우라면 Git for Windows 설치를 권장해요. 설치하면 Bash 도구를 쓸 수 있고, 없으면 PowerShell을 셸 도구로 써요. WSL에서는 Git for Windows가 필요 없어요. (출처: Claude Code 설치 문서)

## 3단계: 버전 확인, 로그인, 첫 요청

### 새 터미널에서 버전 확인

설치가 끝나면 새 터미널을 열고 아래 명령을 입력해요.

```bash
claude --version
```

버전 번호가 나오면 설치는 끝났어요. 'claude를 찾을 수 없다'는 메시지가 나오면 설치 경로가 PATH에 없다는 뜻이에요. PATH 환경변수에 설치 경로가 들어 있는지 확인하세요. 지금 PATH는 macOS·Linux에서 echo $PATH, PowerShell에서 $env:Path로 볼 수 있어요.

### 로그인

터미널에서 `claude`를 실행하고 브라우저 안내를 따라 로그인해요. `ANTHROPIC_API_KEY` 환경변수를 설정해 두고 사용을 승인하면 로그인 절차를 건너뛰어요. (출처: Claude Code 설치 문서)

### 작업할 폴더에서 첫 요청

저장소에서 시작하는 공식 quickstart 절차는 확인되지 않았어요. 다만 프로젝트용 스킬이 해당 저장소에서만 적용된다는 문서 내용을 보면, 작업할 폴더로 이동해서 실행하는 흐름이 자연스러워요.

```bash
cd 내-프로젝트-폴더
claude
```

첫 요청은 이런 식으로 해 보세요. 제가 만든 예시예요.

- "이 저장소의 폴더 구조와 각 폴더가 하는 일을 설명해 줘"
- "README를 읽고 로컬에서 실행하는 방법을 순서대로 정리해 줘"

처음엔 파일을 고치는 요청보다 읽고 설명하는 요청이 안전해요. 결과를 믿을 만한지 먼저 감을 잡으세요.

## 4단계: 스킬 설정

스킬은 `SKILL.md` 파일로 클로드의 기능을 넓히는 방식이에요. `/스킬이름`으로 직접 부를 수 있고, 클로드가 필요하다고 판단하면 알아서 불러오기도 해요. 폴더 이름이 곧 명령어 이름이에요.

| 구분 | 저장 위치 | 적용 범위 |
|------|------|------|
| 개인용 | 홈 폴더 .claude/skills/<스킬명>/SKILL.md | 모든 프로젝트 |
| 프로젝트용 | 저장소 안 .claude/skills/<스킬명>/SKILL.md | 그 저장소만, 커밋하면 팀과 공유 |

### 가상 예시: 커밋 전 점검을 /review-check 하나로

아래는 설명을 위해 만든 가상의 예시예요. 파일에 꼭 들어가야 하는 항목이 있는지 같은 정확한 형식은 [공식 스킬 문서](https://docs.claude.com/en/docs/claude-code/skills)를 먼저 보고 그 예시를 따르세요.

커밋할 때마다 "바뀐 파일 보고 오타랑 안 쓰는 변수 찾아 줘"를 다시 치는 대신, 이 요청을 스킬로 저장해 두는 장면이에요.

폴더 만들기(macOS·Linux·WSL):

```bash
mkdir -p "$HOME/.claude/skills/review-check"
```

폴더 만들기(PowerShell):

```powershell
New-Item -ItemType Directory -Force "$HOME\.claude\skills\review-check"
```

그 폴더 안에 SKILL.md를 만들고 지시를 적어요. 최소한의 모양은 이 정도예요.

```markdown
# review-check

커밋 전에 바뀐 코드를 점검한다.

1. 이번에 수정한 파일 목록을 정리한다.
2. 오타, 쓰지 않는 변수, 남겨 둔 디버그 출력을 찾는다.
3. 문제마다 파일 이름과 고칠 방법을 짧게 적는다.
```

확인은 간단해요. 저장소 폴더에서 `claude`를 실행하고 `/review-check`를 입력하세요. 점검 결과가 돌아오면 성공이에요. 명령이 잡히지 않으면 폴더 이름이 review-check인지, 파일 이름이 SKILL.md인지부터 보세요.

기존 `.claude/commands/` 파일도 계속 동작해요. 커스텀 명령이 스킬로 통합됐기 때문이에요. 기본 제공 스킬로는 `/doctor`, `/code-review`, `/batch`, `/debug`, `/loop`, `/claude-api` 등이 있어요. (출처: Claude Code 스킬 문서)

바로 해볼 것: 매주 반복하는 요청 하나를 골라 개인용 스킬로 먼저 만들어 보세요. 잘 돌아가는 걸 확인한 뒤 프로젝트용으로 옮겨 팀과 나눠도 늦지 않아요. 반복 업무를 줄이는 다른 방법은 [AI 자동화 글 모음](/categories/ai-automation)에 정리돼 있어요.

## 자주 하는 실수와 주의점

- Homebrew로 설치하고 업데이트를 잊음: 네이티브 설치는 백그라운드에서 자동 업데이트되지만 Homebrew 설치는 아니에요. 직접 챙기세요. (출처: Claude Code 설치 문서)
- 웹 채팅으로 한도를 먼저 씀: 웹에서 긴 대화를 많이 한 날엔 클로드 코드에 쓸 몫도 줄어요. (출처: Claude 요금제 페이지)
- 공유 스킬의 폴더 이름을 바꿈: 명령어 이름도 같이 바뀌어요. 팀이 쓰는 스킬이라면 바꾸기 전에 알리세요.

## FAQ

### Q1. 저장소에서 CLAUDE.md나 /init을 쓰라던데요?

CLAUDE.md와 /init의 동작은 확인되지 않았어요. 공식 Claude Code 문서의 quickstart 페이지에서 확인하세요. 이 글은 문서로 확인된 스킬 설정까지만 다뤘어요.

### Q2. 터미널이 낯선데 꼭 명령어로 써야 하나요?

아니에요. macOS, Windows, Linux용 데스크톱 앱이 있어요. 다른 AI 도구와 비교해 보고 싶다면 [AI 도구 글 모음](/categories/ai-tools)도 참고하세요.

### Q3. 회사가 AWS나 구글 클라우드를 쓰는데, 그쪽으로도 되나요?

돼요. 아마존 베드록, 구글 클라우드 Agent Platform, 마이크로소프트 Foundry 같은 서드파티 API 제공자를 통해서도 쓸 수 있어요. 구체적인 연결 방법은 공식 설치 문서를 보세요. (출처: Claude Code 설치 문서)
